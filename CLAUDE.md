# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

    cargo test                          # unit tests; run from the repo root, they load assets/ by relative path
    cargo test <name>                   # single test, e.g. cargo test falling_box
    cargo test --release -- --ignored --nocapture   # benchmarks in src/bench.rs (`bench`, and `shake` with SEEDS=40 for more seeds)
    cargo run --example camera          # also: physics, raycast, text (F3 toggles the debug overlay)
    cargo fmt && cargo clippy --all-targets -- -D warnings
    cargo test --no-default-features    # lean build: software renderer, no audio

`ENGINE_MUTE=1` silences audio, `ENGINE_STATS=1` logs frame timings, `ENGINE_RENDERER=soft|gpu|auto` picks the renderer, `ENGINE_SCALE=n` scales the window, `ENGINE_RECORD=path` / `ENGINE_REPLAY=path` record and replay input. The window needs an X display (WSLg works); `minifb` is built with the `x11` feature only, because its Wayland backend spams EGL/Zink errors under WSL.

Commits are checked by pre-commit (`pre-commit install`): Conventional Commits (`feat|fix|refactor|perf|test|docs|chore|ci|build`, optional scope), plus `cargo fmt --check` and clippy with `-D warnings` for both the default and the `--no-default-features` build. `.github/workflows/ci.yml` runs fmt, clippy (both builds) and `cargo test` (both builds) on Linux, Windows and macOS on every push to `main`; `docs.yml` publishes the rustdoc to GitHub Pages. When asked to commit and push, commit on `main` and push `main` directly (no feature branch, no PR), with no `Co-Authored-By` trailer.

## Project conventions

- Comments are allowed but rare: add one only where the code cannot show *why* (a non-obvious constraint, workaround or invariant). Keep it to one short, plain line. Never restate what the code does, and skip doc comments on self-explanatory items. The owner dislikes comment-heavy code.
- `rustfmt.toml` uses `max_width = 120` and `use_small_heuristics = "Max"`. Run `cargo fmt` rather than formatting by hand.
- Keep changes minimal; measure before optimizing (see `src/bench.rs`). Put measurements in commit messages, not here.
- Reuse before writing: `Rect::center/contains/edges/penetration/overlaps`, `Sprite::bounds`, `DrawCmd::new`, `Paint::region`, `assets::read_text(_if_exists)` and `write_atomic`, and the `sub/dot/apply/shove` helpers in `physics/mod.rs` already exist.
- Prefer in-house code or tiny crates over new dependencies: build time is a stated concern. Code touching `wgpu` or `rodio` stays behind `#[cfg(feature = "gpu" | "audio")]`; the lean build must keep compiling.

## Architecture

`engine` is a library crate. Source is grouped by area (`app/`, `render/`, `ecs/`, `assets/`) and `src/lib.rs` re-exports the public API at the crate root, so games and internal code use flat `engine::X` / `crate::X` paths. Games use only that API, never `minifb` directly.

**Loop and scenes (`app/`).** `run(cfg, first)` owns the window, a fixed-timestep accumulator (`Config::tick_hz`) and a scene stack. A scene implements `update(&mut Ctx) -> Trans` and `draw(&self, &mut Gfx)`. Only the top scene updates; every scene draws, bottom first. `Trans` is `None/Push/Pop/Replace/Quit/Fade`. `on_enter` runs when a scene joins the stack and `on_exit` when it leaves; a `Push`ed overlay does not touch the scene beneath. Game scenes call `ctx.cam().reset()` in `on_enter`, and anything that outlives a scene (music) is stopped in `on_exit`. The engine does not handle Esc; scenes do.
- `Ctx` fields are crate-private and reached through accessors (`input()`, `assets()`, `audio()`, `cam()`, `rng()`, `dt()`, `size()`). Each borrows the whole `Ctx`: read `let dt = ctx.dt();` into a local before `ctx.cam().follow(.., dt)`, never nest them.
- One fixed step is the function `step` (replay input, fade tick, top scene update unless a fade is darkening, `end_step`, camera and audio ticks), so the order is tested with fake scenes without a window. `run` only adds window, drawing and timing.
- `Trans::Fade(inner, secs)` darkens over half of `secs`, applies `inner` at full black, then brightens. The top scene does not update while it darkens.
- `run` draws only on frames that ran a tick (and the first, and after a resize); otherwise it sleeps until the next tick. F3 is tracked in `run` itself because `Input::pressed` refreshes only once per step.
- `run` panics naming the field if `tick_hz` is not positive or `w`/`h` is 0.

**Rendering (`render/`).** `Gfx` does not draw: it records `DrawCmd`s into a per-frame list in screen space, and `run` hands the list to a backend. `DrawCmd` is the whole contract, so a backend only has to consume that list; `render/` knows nothing about the ECS.
- `Soft` rasterizes into a `Vec<u32>`; `Gpu` (wgpu) turns every command into quads. Both must give the same pixels: `gpu_output_matches_the_software_rasterizer` renders one scene on both and compares (skips without an adapter; `ENGINE_DUMP=<dir>` writes `soft.png` and `gpu.png`). Fill edges are truncated and sprite, region, tile and mask origins floored the same way on both, and scaled or turned sprites are sampled `SAMPLE_BIAS` towards the next texel so ties break the same way.
- `Config::renderer` is `Auto` (GPU only if a non-CPU adapter can present, else `Soft` with one stderr line), `Gpu` or `Software`. Under WSL `run` sets `GALLIUM_DRIVER=d3d12` itself when `/dev/dxg` exists. The GPU texture cache keys sprites by `Arc` pointer and drops entries nobody else references each frame.
- The camera is applied in `Gfx::draw`, not in `fill`/`blit`/`text`, so HUD drawn directly stays in screen space. `gfx.line(a, b, c)` (a pixel thick, ends included: a turned flat rect, so both backends agree) and `gfx.circle(center, r, c)` (one fill per row, pixel centres within `r`) are screen-space too; `Gfx::text_width(s, scale)` measures the 8x8 font. `Gfx::draw` sorts by layer (stable).
- `Tilemap::draw_list(gfx.view())` gives one or two `Tiles` commands (behind and in front of entities), or none.
- Every `DrawCmd` has a `Transform { angle, sx, sy }` (radians, clockwise on screen; scale about the centre of the drawn quad; negative mirrors; zero draws nothing). `Glyph`, `Mask`, `Tiles`, `Outline` and `Clear` ignore it. `Soft` takes `scaled_blit` for scale without angle and `warp` for turned shapes; both must keep the same arithmetic (a test compares them).
- `Soft::fill_alpha` uses the SWAR `blend` compiled plain and with AVX2, picked at run time. The two must stay bit-identical (a test checks it).
- `Config::scale` (or `ENGINE_SCALE`) makes the window `scale x` the internal resolution; the game stays in internal pixels. `Config::resizable` letterboxes the picture (`letterbox` in `render/gfx.rs`). Fullscreen (`Config::fullscreen`, `ctx.set_fullscreen/toggle_fullscreen/fullscreen()`, F11 handled in `run`) is not a minifb call: `app/fullscreen.rs` sends the window manager an EWMH `_NET_WM_STATE_FULLSCREEN` message through `x11-dl` (already in the tree as minifb's dependency; the dependency is `cfg`'d to unix without macOS). `run` asks after the second presented frame, and on failure prints one line and puts the flag back; the existing resize path letterboxes the picture. Checked on WSLg with `xwininfo` (1920x1080 and back, also for a non-resizable window); `cargo test -- --ignored fullscreen` repeats that on a display. Elsewhere it is an `Err` and ignored.

**Camera (`render/camera.rs`).** State lives in `ctx.cam` and advances in the fixed update. `follow(target, world_size, dt)` eases and clamps (the first call snaps), `cut()` makes the next `follow` snap, `shake(amplitude, secs)` jitters, `set_zoom`/`zoom_to` zoom about the middle of the view (0.25..=8). `run` copies the final whole-pixel offset and zoom into `gfx.cam` / `gfx.zoom`. With zoom != 1 flat rects get each edge rounded so neighbours keep sharing edges, sprites scale about their centre to cover the rounded rect, text scale is `round(scale * zoom)` and at least 1, and a `Tiles` batch is split into one `Region` per tile. A NaN follow target is ignored. The camera is one per app and persists across scenes.

**ECS (`ecs/`).** `World` and `Entity` come from `hecs` (0.11: `query` iterates plain items; ask for `Entity` in the tuple when needed). Components must be `Send + Sync`, which is why `Assets` hands out `Arc<Sprite>`. The engine ships `Body(Rect)`, `Vel`, `Look`, `Anim`, `Collider`, `Layer`, `Filter` and the systems `movement`, `animate`, `particles`, `draw_list` (sorted by `Layer`, stable, so spawn order breaks ties; `Anim` entities follow `Look` ones in a layer). Games define their own components and logic inside `Scene::update`.
- Particles are ordinary entities made by `burst` and advanced by `particles(world, dt)`, marked by the `Particle` component; they carry their own velocity instead of `Vel`.
- `Sprite::new(w, h, pixels)` makes a sprite in code (0xAARRGGBB, row by row).
- `Anim` treats a sheet as a grid of equal frames: a row is a clip, `play(row, frames, fps)` restarts only when the row changes. `Clip::new(row, frames, fps)` / `Clip::timed(row, &[secs])` (own time per frame) `.once()` (holds the last frame, `anim.finished()`) `.event(frame, "name")` (fires when that frame starts, read with `anim.fired("name")` after `animate`, also for the first frame and after a loop wrap); `anim.play_clip(&clip)` or `start(&clip)` (always from the first frame). `AnimStates::new().state("idle", clip).state("hit", clip.once()).then("hit", "idle")` next to an `Anim` plays the clip of its current state; `set("name")` asks for one (panics on an unknown name) and a finished once-clip moves on by `then`.

**Collisions.** Entity vs entity: `collisions(&world)` reports overlapping `Body` + `Collider` pairs (sort-and-sweep on x) with penetration per axis; resolving is up to the game or `Physics`. Entity vs terrain: `Tilemap::slide` returns a `Slide { rect, blocked_x, blocked_y }`, moves axis by axis and assumes less than a tile per step. `Filter { group, mask }` (optional) limits who meets whom: two entities meet only when each one's mask holds a bit of the other's group; tiles are group `Filter::TERRAIN` (bit 31). A `Collider` without a `RigidBody` is a trigger. `raycast(&world, from, dir, max, mask)` scans colliders and returns a `RayHit { entity, t }`; `RayIndex::new(&world)` is a grid snapshot for many rays (rebuild it after bodies move); `raycasts(&world, &[Ray::new(from, dir, max, mask)])` takes the rays together and builds that grid itself from 8 rays on; `query_rect` lists colliders in an area. None of them look at tiles.

**Physics (`ecs/physics/`).** `mod.rs` (bodies, step, solver, sleeping, joints), `contact.rs` (contact generation: `touch` and the box, tilted box and circle cases) and `tests.rs`. In-house boxes and circles with rotation, no dependency.
- Give an entity `Body` + `Vel` + `RigidBody::dynamic(mass)` (`.circle()`, `.bounce`, `.friction`, `.spin`) and call `physics.step(&mut world, Some(&tilemap), dt)` once per fixed update. `RigidBody::fixed()` is a wall. Build `Physics::default()` and set the public `gravity` and `iterations` afterwards; the rest is private. Entities without `RigidBody` are ignored.
- Rotation is opt-in by adding a `Transform`: physics reads and writes `angle` and turns the body about the centre of its (unturned) `Body` rect. A `fixed` body with a `Transform` is a tilted wall. `sx`/`sy` are ignored.
- Two bodies bounce by the smaller restitution, so walls need one too (`RigidBody::fixed().bounce(e)`, `Tilemap::bounce`).
- The step: gravity, semi-implicit Euler, solid tiles near each body joined as fixed boxes, pairs from `Sweep`, `touch`, sequential-impulse passes with accumulated impulses and Coulomb friction, then positional correction. Contacts are warm-started from `cache`; every `prepare` must run before any replay or piles explode.
- Untilted boxes take their contact direction from where the boxes were *before* the step, not from the current overlap (two regression tests; each fails without it). `step` cuts the step into substeps until no body moves more than `TRAVEL` (an eighth of its smaller side), up to `MAX_SUBSTEPS`; past that a fast body can still pass a thin wall. No true CCD. Only a fast body whose swept bounds meet another node or a solid tile counts (`substeps`), so a body that fell out of the world or flies through empty space does not keep every step at 16 substeps.
- Tile contacts are filtered so floors have no ghost bumps (`behind` in `find_hits`, `is_hidden`, both through `hides`); a one-way tile above a face does not hide it, or dropping through a platform on the ground passes the ground too. Tiles always go second in a pair.
- Sleeping: a body below 5 px/s (its rim included: spin times half the diagonal) for half a second sleeps (acts as a wall, `Vel` zeroed). It wakes when a body faster than `WAKE_SPEED` overlaps it, when the game changes its `Body`/`Vel`/spin/angle/`Filter`, or when gravity, the tile map (`Tilemap::stamp`) or a supporting body changed (a wall's rect, `Filter` or one-way flag counts). Jointed bodies never sleep. `physics.asleep(e)` / `wake(e)`.
- Joints, looked up by entity each step (a despawned end removes the joint for good) and otherwise kept until `clear_joints()`; a joint added to a sleeper wakes it: `rod(a, b, length)` and `rope(a, b, length)` between body centres; `spring(a, b, length, hz, damping)`, a soft constraint (frequency and damping ratio of the mass it moves, one accumulated impulse per substep, no positional correction; `hz` 0 adds nothing); `hinge(&world, a, b, anchor)`, a pin through a world point that lets both bodies turn about it (needs a `Transform` to turn; solved as a 2x2 point constraint with the angular terms, and positions are pulled together afterwards).
- `RigidBody::kinematic()` is a platform physics moves by its `Vel` (no gravity, never pushed; without a `Vel` it is a wall); a sleeper on it is woken because the walls-moved check sees it move, and friction carries a box along. `RigidBody::fixed()/kinematic().one_way()` holds a body only when the contact presses it onto the top and it was above before the step (`passes_one_way`, a 2 px grace); drop through by clearing a `Filter` bit. A `Tile { one_way: true, .. }` (Tiled property `one_way`) is the same for a tile: solid only from above, with group `Filter::PLATFORM` (bit 30), so clearing that bit in a mask drops a body through platforms but not through the ground; a ghost that ignores all tiles clears `TERRAIN | PLATFORM`. `Tilemap::slide` also lets bodies pass one-way tiles sideways and upwards. Rays and paths still see them as solid.
- Slope tiles (`Tile { slope: Some(Slope::BottomRight) .. }`, Tiled string property `slope` = `bl`/`br`/`tl`/`tr`, the corner with the right angle) are exact right triangles for physics: `contact.rs` clips a box (turned or not) against the triangle with the same separating-axis scheme as `tilted_boxes`, and `circle_triangle` handles circles. The tile's own edge is the reference face, and the seam filters (`behind`, `is_hidden`) are skipped for slopes. A continuous ramp is a staircase of slope tiles, one row higher per column (a row of the same slope is a sawtooth), with solid tiles under and beside it. `Tilemap::slide` climbs and descends them (`Slope::sink` is how far the box reaches into the triangle: a sink up to the step sideways is climbed, a bigger one is a wall; a box that stood on a slope is dropped back onto it so walking down does not float; standing on or landing on a slope reports a blocked y), while `raycast` and `path` still treat a slope tile as a full block. Tile friction is a fixed 0.4 and pairs combine as `sqrt(a * b)`, so a body needs `friction` above about 2.5 to hold on a 45 degree slope.
- Contact events: `physics.events()` / `events_of(e)` / `grounded(e)` / `ground(e)` list what touched during the last `step` as `ContactEvent { a, b: Option<Entity> (None for a tile), normal (a to b), impulse (hardest push of any substep), began }`. Substeps are merged by pair so a bounce that left again within the step still shows, and a pair at rest keeps being listed while both are asleep or immovable. A game reading them to walk on a moving platform uses `ground(e).other(e)` for the body underneath.
- `ecs/fx.rs` is a small multiplicative hasher (`FxMap`, `FxSet`) for the engine's own keys. `Sweep` keeps its x order between calls and insertion-sorts it.
- The physics is bit-for-bit repeatable (a test checks it), which replay relies on. Tuning constants (`TRAVEL`, `HEAVY_RATIO`, correction passes, `WAKE_SPEED`) were set against the `shake` benchmark in `src/bench.rs`; rerun it with many seeds before changing them.

**Saving a world (`ecs/persist.rs`).** `WorldFile::new().component::<Body>("body").component::<Hp>("hp")` registers the components worth saving; `to_text(&world)` / `save(&world, path)` write a `[entity]` line and one `name = value` line per registered component (entities with none are left out, sorted by entity id, so saving what was loaded gives the same text), and `spawn_from(&mut world, text)` / `load(&mut world, path)` add the entities back and return them (clear the world first to replace it). A game's component implements `Persist` (`write` and `read`; impls exist for `f32`, `i32`, `u32`, `bool`, `String` and the engine's `Body`, `Vel`, `Collider`, `Layer`, `Filter`, `Transform`, `RigidBody`). An unknown or repeated component name or an unreadable value is an `Err` naming the line, and nothing is added. Not saved: unregistered components, `Look::Sprite`, animation, links between entities (an `Entity` is not stable across a load), and `Physics` itself (sleep, contact cache, joints).

**Time helpers (`app/time.rs`).** `Timer::once/looping(secs)` accumulate the fixed `dt` given to `tick(dt)`; `fraction()` is progress. `Ease` curves and `Tween::new(from, to, secs, ease)`. `Timer::once` panics on a negative or NaN duration, so anything that takes a time from a game clamps it to 0 first.

**Panels and atlases.** `gfx.blit_nine(&sheet, src, margin, &dest)` draws a framed region as a panel of any size: corners at natural size, edges and middle *repeated* (not stretched), only pieces on screen recorded. `Atlas::parse(text, sheet)` / `Atlas::load(path, sheet)` names regions from `name x y w h` lines; `atlas.get(name)` panics on an unknown name.

**Style, parallax and Vec2.** `DrawCmd::style` (`Style { flash, flash_amount, opacity, blend }`, `Style::PLAIN.flashed(0xffffff, 200).faded(120).additive()`) is followed by `Sprite`, `Region`, `Color` and `Alpha` paints only; an ECS entity gets it from a `Style` component through `draw_list`, and `gfx.blit_styled` draws one straight to the screen. Soft routes a non-plain style through a different pixel function (generic `px` closures in `blit_region`/`scaled_blit`/`warp`, so the plain path costs nothing); the GPU adds a flash attribute to the vertex and a second pipeline for `Blend::Add` (batches split by it); a test renders flashes, fades and additive blends on every path of both backends. `gfx.draw_parallax(cmds, (fx, fy))` draws with the camera counted by that factor (whole pixels) and `gfx.background(&sprite, factor, (repeat_x, repeat_y))` repeats a picture over the screen, straight to the screen and ignoring zoom. `Vec2` (`vec2.rs`) is the public vector type with operators and `From` conversions to and from tuples and arrays; the public API takes (`impl Into<Vec2>`, so tuples still work) and returns it (`Rect::center/penetration`, `marks`, `pixel_size`, `Input::mouse`, `mouse_world`, `Camera::to_world`). `Physics::gravity`, `Gfx::cam`, `Light::new` and `Rect::contains` use it too. `Rect` is passed by value everywhere (`Rect::new(x, y, w, h)`). Still tuples: the engine's internal `V2`.

**Light and screen effects (`render/light.rs`).** `Blend::Multiply` (`Style::PLAIN.multiplied()`) multiplies what is behind a `Sprite`, `Region`, `Color` or `Alpha` paint by its colour, mixed towards white by its alpha and `opacity` (white leaves the picture alone, black blackens it): Soft's `mul_flat`, a third GPU pipeline with the `fs_mul` entry and blend factors `Dst`/`Zero`. Everything else is baked on the CPU into an image of the canvas's size and drawn once with that blend, so both backends show the same picture by construction: `LightMap::new(w, h)` with `clear(ambient)`, `add(Light::new(x, y, radius).colored(c).intensity(i))` (screen pixels) or `add_world(&gfx, light)` (through the camera and zoom), then `draw(&mut gfx)` once after the world and before the HUD; a light brings the colours it falls on back up to themselves (falloff `(1 - d^2/r^2)^2`, channels saturate) and never beyond, so a glow is an additive sprite instead. `vignette(w, h, strength)` and `scanlines(w, h, dark)` make the image once and `gfx.multiply(&image)` lays it over the picture so far. The light map reuses one `Sprite` (`swap_pixels` bumps its version), and the GPU writes the new pixels over the same texture when the size is unchanged instead of making a new one. A test renders a lit scene with a vignette and scanlines on both backends for two frames with a moving light. `examples/platformer.rs` has N for a night with a torch.

**Audio (`assets/audio.rs`).** `ctx.audio().play(path)` fires a one-shot, `play_with(path, Sound::new().pan(-0.5).pitch(1.2).volume(0.8))` one with its own pan (equal power, played as mono through `ChannelVolume`), pitch (a speed multiplier, 0.25 to 4) and volume; `music(path)` loops one track. `play`/`play_with` return a `Voice` for `stop(voice)` and `is_playing(voice)` (handed out even when silent); `Sound::new().looped()` repeats until stopped; `pause_music`/`resume_music` hold the track. WAV and OGG Vorbis are decoded (rodio features `wav` and `vorbis`; the OGG path was checked with a real file once, there is no sound file in the repo to test it). Volumes are a master (`set_volume`) times a bus: `Bus::SFX` and `Bus::MUSIC` are built in (`set_bus_volume(Bus::MUSIC, v)`) and `audio.bus("voice")` makes or finds a named one; `Sound::new().on(bus)` sends a one-shot there, `set_bus_volume(bus, v)` (clamped to 0..=1, NaN is silence) also retunes what is already playing, and `fade_bus(bus, to, secs)` moves it over time, ending exactly on `to` (duck the music under speech, fade the effects under a pause menu), `fade_in_music`/`fade_out_music`, and `set_max_sounds` (a new sound cuts off the oldest). The numbers live in `Mix`, shared by the real and silent builds. Without the `audio` feature, with `ENGINE_MUTE=1`, or with no output device, every call is a no-op and sound files are not read. Under WSL, ALSA needs `libasound2-plugins` to find WSLg's sound server. Only the numbers are tested; nothing was listened to.

**Levels.** `Tilemap::load(path, size, sheet)` reads a plain-text grid: `#` ground and `+` brick are solid, `.` or space is empty, any other character is a marker (`map.marks(b'P')`). `load_with` takes a custom `Tile { ch, id, solid, front, auto }` legend; `auto` makes `id` the first of 16 sheet tiles chosen by joined neighbours (up 1, right 2, down 4, left 8). `front` tiles draw over entities. Several maps drawn one after the other are layers (each `gfx.draw` call keeps its order). A sheet may have several rows: ids run along the first row and then the next (`Paint::tile_src(id, size, sheet_w)`). `map.raycast(from, dir, max)` walks the tiles by DDA and returns `TileHit { t, tile, normal }` (the map's left and right edges are solid at any height, as for bodies); it does not look at entities, so compare its `t` with `raycast`'s. `map.path(from, to, diagonal)` / `path_with(.., open)` is A* over the tiles that are not solid (`render/path.rs`; 10 per straight step, 14 per diagonal, no corner cutting), `cell_of(point)` and `cell_center(cell)` convert. `Tiled::load(path, sheet)` reads a `.tmx` (finite, orthogonal, square tiles, one tileset embedded or `.tsx` without spacing or margin, layers saved as CSV, no flips, at most 255 tiles) into one `Tilemap` per layer (`tiled.layer("name")`) plus `objects` (`TiledObject { name, kind, x, y, w, h, props }`); a tile is solid with a bool property `solid` and drawn in front with `front`; the XML reader is in-house. `Spawner::new().on("coin", |world, obj| world.spawn(..)).skip("spawn").spawn(&mut world, &tiled.objects)` turns objects into entities by their `kind` (the later handler of a kind wins; a kind nobody handles is an `Err` naming the object and nothing is spawned). Rows must be ASCII and only trailing newlines are trimmed. Cells are `(usize, usize)` (`tile(cell)`, `set(cell, id)`, `one_way(cell)`, `slope(cell)`, `cell_of`, `path`); only `TileHit::tile` is `(i32, i32)` because the map's side edges count as solid outside it. `set(cell, id)` panics for an id past the sheet. Every `load` returns a `Result` and takes the path first (`Sprite::load`, `Tilemap::load`, `Tiled::load`, `Atlas::load`, `Font::load`, `Save::load`); `from_ascii` panics where `try_from_ascii` returns `Err`.

**Hot reload (`assets/watch.rs`).** `Config::hot_reload` (default on in debug builds) polls modified times twice a second. `Assets::sprite` and `ctx.load_bindings` watch their files; a changed image is swapped *inside* the existing `Sprite`, so every held `Arc<Sprite>` shows it, and the GPU re-uploads on a version change. Backends skip a frame or tile whose source rect no longer fits a smaller replacement sheet. Decode or parse errors keep the last good data and print one line. For other files: `ctx.watch(path)` once, then `if ctx.changed(path)`.

**Assets and input.** `ctx.assets()` caches sprites and fonts by path, never evicted. Input is latched between steps: a tap that ends before the step still counts. Games read input by action name, never by key: `ctx.bind("jump", &[Key::Space])` (once, usually in the closure passed to `run`), then `input().down/pressed/released/repeated/axis` (`repeated` is `pressed` and then, held, again after 0.4 s at 30 a second, counted in steps so replay keeps it; `key_repeated(Key)` too, which `TextField` uses for Backspace). Querying an unbound action panics. `key_down(Key)` is the raw escape hatch. Bindings live in a text file of `action = Key Key pad.A` lines (`#` comments, `minifb::Key` variant names, case-insensitive): games bind defaults, then call `ctx.load_bindings("input.txt")`. A missing file is fine; a malformed one, or one naming an action the game never bound, returns `Err` and applies nothing. A reload starts from the defaults the game had before the first file. `ctx.save_bindings(path)` writes only what differs from those defaults.

**Mouse and gamepad.** `input().mouse()` is `Some((x, y))` in canvas pixels (`None` outside the picture or window), `ctx.mouse_world()` adds the camera, and `mouse_down/pressed/released`, `wheel()` use the same per-step edges. `Pad` buttons bind to actions with `ctx.bind_pad` (`pad.<Name>` in `input.txt`); `PadState` reads the Linux joystick API (`/dev/input/js0`, Xbox-style numbering) with no crate, and the d-pad and left stick both read as Up/Down/Left/Right. `input().pad_axis(PadAxis::..)` gives analog values. The decoding is tested with synthetic events only; no real pad was tried (WSL has no `/dev/input`).

**Record and replay (`app/replay.rs`).** `ENGINE_RECORD=path` writes the seed and tick rate, then the held keys, pad buttons and mouse of each fixed step when the run ends normally; `ENGINE_REPLAY=path` feeds them back and quits when they run out, refuses a file recorded at another `tick_hz`, and polls no files for hot reload meanwhile. Not recorded: analog axes, the wheel, typed characters, and the bindings (keys are recorded, so replay with the same `input.txt`). It reproduces a run only if the game takes all randomness from `ctx.rng()` and reads no wall clock. A real recorded session has not been replayed.

**Save data (`app/save.rs`).** `Save` is a sorted `key = value` file owned by the game: `load` (missing file is empty, malformed is `Err`), `set`, `get::<T>`, `get_or`, `remove`, `save` (atomic write via `assets::write_atomic`). Keys may not contain `=` or `#` (`set` panics). Unparsable values read as missing.

**Fonts and Korean text.** `gfx.text` is the 8x8 ASCII font. `ctx.assets().font(path)` loads a BDF font (in-house parser in `render/bdf.rs`, packed into one atlas, drawn as `Paint::Mask`), and `gfx.text_font(&font, s, x, y, color)` / `text_font_scaled` draw it; multiply `font.width` and `line_height` by the scale yourself. `assets/fonts/galmuri9.bdf` is Galmuri9 (SIL OFL) cut down to ASCII, compatibility jamo and all 11172 syllables; a character the font lacks draws as `?`. The pre-commit large-file limit is 2000 KB for it.

**Debug tools (`debug.rs`).** F3 is the engine's own overlay (fps, ticks, work time, command count). `Inspector::new()` (F4 opens it, a left click picks the entity under the cursor on the highest layer) lists the components of the picked entity: the engine's are known, `register::<T: Debug>("name")` or `register_with("name", |world, e| ...)` adds yours; call `update(ctx, &world)` and `draw(gfx, &world)`. `Console::new()` (backquote opens it, Enter sends, Up/Down recall, Escape closes; Korean works through `TextField`) only reads and prints: `update(input)` returns the `Command { name, args }` of a finished line and the game decides what it does, `print(text)` adds a line, `draw(gfx, &font)`; the game should ignore its own keys while `is_open()`. `examples/platformer.rs` uses most of the newer parts together (moving and one-way platforms, one-way and slope tiles from `assets/levels/platformer.txt`, events, animation states, flash, parallax, inspector, console); its controller drops a grounded body's upward speed (`vel.y.max(0.0)`), or a slope launches it at the crest. Three tests in `physics/tests.rs` walk that level with the same controller.

**UI (`ui.rs`).** Immediate-mode helpers: `draw_panel`, `draw_bar`, `Menu`, `Button`, `Checkbox`, `Rebind`, `TextField`, and the stateless `hovered`, `clicked`, `slider`. Every widget has one shape: placed when it is made (a `Rect` for one that fills an area: `Button`, `ScrollList`; `x, y` for one that sizes itself: `Checkbox`, `Menu`, `TextField`, `Rebind`; both kept in public fields), `update(ctx.input(), ..)` in `Scene::update` (`Rebind::update` takes the `Ctx` because it rebinds), `draw(gfx, &font, &theme)` in `Scene::draw`. `Theme` holds the colours (`Theme::default()`). `Menu::update` also takes the mouse (hover highlights after the cursor moves, a click picks). Action names are the caller's and must be bound. `Layout::column/row(area, gap)` with `.next(size)` / `.rest()` and `grid(area, cols, rows, gap)` cut an area into rectangles. `wrap(font, text, max_px)` breaks lines at spaces, line breaks and, for a word too long (Korean without spaces), at any character; `draw_wrapped` draws what fits a rectangle and returns the full line count. `ScrollList` (`update(input, rect, font, up, down, accept)`, `draw`) moves the highlight by actions, scrolls three rows a wheel notch over its rectangle (the highlight may leave the view; keys and clicks bring it back) and picks by click or accept. `Focus` moves among a slice of rectangles by the four direction actions (nearest centre ahead, sideways drift counted double), follows the mouse and returns the index on accept or click, so keyboard and pad can drive `Button`s; `Menu` and `ScrollList` already take pad buttons through actions bound with `bind_pad`. `TextField` composes Hangul itself (`src/hangul.rs`) because minifb has no input method: jamo arrive from a Korean X layout or, after `set_korean(true)` (RightAlt), from letter keys. The composing logic is tested; typing in a real window was not tried.
